# ADR 001: Subscription Purchase & Entitlement Verification Architecture

## Context
Fit10 is an offline-first Android application monetized via auto-renewing subscriptions ("Fit10 Pro") through Google Play Billing. Currently, subscription purchases are queried and validated on-device using the Google Play Billing Library (`BillingClient`).

While client-side validation using the official Play Billing Library protects against casual piracy and operates completely offline, client-side only checks have fundamental architectural security limitations:
1. **Rooted Devices and Modified Binaries:** On rooted devices or modified APKs/emulators, tools like Lucky Patcher, Frida, or customized system frameworks can hook `BillingClient` responses or bypass local SharedPreferences/DataStore caches to grant Pro status without a valid transaction.
2. **Subscription Lifecycle & Renewal Latency:** Client-side querying only detects state changes when the user actively opens the application. Events like out-of-app cancellations, credit card billing retries, chargebacks, and family sharing revocations cannot be processed proactively.

## Architecture Design: Two-Tier Entitlement Verification

To balance offline-first UX with robust fraud prevention, Fit10 establishes a clean separation between billing retrieval and entitlement verification through the `EntitlementVerifier` interface.

```
                              ┌─────────────────────────────────────────┐
                              │           Google Play Store             │
                              └───────▲─────────────────────────▲───────┘
                                      │                         │
                        Purchase Flow │                         │ RTDN Webhooks
                                      │                         ▼
                        ┌─────────────▼──────────┐    ┌───────────────────┐
                        │    Fit10 Android App   │    │ Optional Backend  │
                        │                        │    │  Verification API │
                        │  ┌──────────────────┐  │    │ (Cloud Functions/ │
                        │  │BillingRepository │  │    │  Ktor / Spring)   │
                        │  └────────┬─────────┘  │    └─────────▲─────────┘
                        │           │            │              │
                        │           ▼            │              │
                        │  ┌──────────────────┐  │    Verify    │
                        │  │EntitlementVerifier│──┼──────────────┘
                        │  └──────────────────┘  │  (Token & SKU)
                        └────────────────────────┘
```

### Tier 1: Local / Client-Side Verification (`LocalEntitlementVerifier`)
- **Mechanism:** Implements `EntitlementVerifier` directly in the Android app.
- **Workflow:** Inspects purchase state from `BillingClient` (`Purchase.PurchaseState.PURCHASED`), verifies `isAcknowledged`, and ensures the purchase signature was generated by Google Play.
- **Offline Resilience:** Once verified, the entitlement is stored in a private local cache with a strict bounded window (`OFFLINE_ENTITLEMENT_GRACE_WINDOW_MS = 7 days`). If the user remains offline beyond 7 days, a network re-verification is required.
- **Suitability:** Fast, zero backend costs, works out-of-the-box for offline-first MVPs.

### Tier 2: Server-Side Verification Path (Recommended for Scale)
When server-side verification is deployed, replace `LocalEntitlementVerifier` with a remote verifier without modifying UI or business logic:

1. **Google Play Developer API:**
   - The app sends `purchaseToken`, `productId`, and `packageName` to the backend.
   - The backend calls Google Play Developer API:
     `GET https://androidpublisher.googleapis.com/androidpublisher/v3/applications/{packageName}/purchases/subscriptionsv2/tokens/{token}`
   - The response provides authoritative `subscriptionState` (`SUBSCRIPTION_STATE_ACTIVE`, `SUBSCRIPTION_STATE_IN_GRACE_PERIOD`, `SUBSCRIPTION_STATE_ON_HOLD`, `SUBSCRIPTION_STATE_CANCELED`), true expiry timestamp, and order ID.
2. **Real-Time Developer Notifications (RTDN):**
   - Google Cloud Pub/Sub publishes subscription event notifications (e.g. `SUBSCRIPTION_RENEWED`, `SUBSCRIPTION_CANCELED`, `SUBSCRIPTION_ON_HOLD`) directly to the backend.
   - The backend records user entitlement state in real-time.
3. **Pluggable Integration:**
   ```kotlin
   class RemoteEntitlementVerifier(private val apiService: BackendAuthService) : EntitlementVerifier {
       override suspend fun verifyPurchase(purchaseToken: String, productId: String): Boolean {
           return apiService.verifyGooglePlayReceipt(purchaseToken, productId).isSuccess
       }
   }
   ```

## Decision & Trade-offs
- Fit10 currently ships with `LocalEntitlementVerifier` to maintain strict offline-first operation without mandatory user accounts.
- The 7-day offline grace period bounds exposure to unauthorized entitlement replay.
- The `EntitlementVerifier` abstraction ensures server validation can be activated in the future with zero changes to `PaywallScreen`, `ManageSubscriptionScreen`, or `FeatureGate`.
